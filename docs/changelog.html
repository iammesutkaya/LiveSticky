Changelog

Release notes and version history for LiveSticky.

Versions
  • v1.1.250 August 2026
  • v1.1.249 August 2026

v1.1.250

Released

Devvit Wiki V2 integration featuring dual-write support across Old Reddit and New Reddit / mobile apps, parent wiki index auto-creation, and 100% automated wiki section cleanup.

Added

  • Devvit Wiki V2 & Dual-Write Support: LiveSticky now publishes clip compilation pages to both Wiki V1 (Old Reddit) and Wiki V2 (New Reddit & mobile apps). Fixes empty clip archive pages on modern Reddit interfaces.
  • Auto-Managed Wiki Index Page: automatically creates and updates the parent /wiki/livesticky directory landing page, eliminating "livesticky does not exist" errors when navigating to the root wiki section.
  • 100% Automated Wiki Namespace Cleanup: dynamically inspects subreddit wiki pages and automatically unlists/hides legacy or duplicate orphan pages (such as clip_archive) from the wiki navigation sidebar without requiring manual moderator intervention.

Fixed

  • Clip Archive Link Availability: resolved issue where clicking /wiki/livesticky/clip-archive/ on modern Reddit or official mobile apps resulted in an unpopulated blank page.
  • Duplicate Sidebar Entries: resolved duplicate sidebar list items on subreddit wikis by setting legacy non-canonical page paths to unlisted mod-only mode.

v1.1.249

Released

Devvit 0.14.1 platform upgrade featuring self-healing post recovery to prevent duplicate posts, plus single-stream card layout refinements.

Added

  • Self-Healing Post Recovery: powered by Devvit 0.14.1's searchPosts() API. If Redis state is missing or lost (e.g. after a server restart or cache clear), LiveSticky automatically searches the subreddit for active live posts, offline posts, or clip compilations before creating new ones, re-linking and updating existing posts to prevent duplicate posts on Reddit.
  • Upgraded core Devvit SDK packages to v0.14.1.

Fixed

  • Single-Stream vs Multi-Stream Layout Match: unified single-stream (cinematic) and multi-stream card layouts in compact mode. The Reddit live discussion thread pill chip now consistently sits in the info section on the right, preventing chip collisions inside the thumbnail image box.
  • Improved responsive 16:9 thumbnail cropping with top-centered object positioning on desktop and embedded demo containers.

v1.1.244

Released

A big update to the stream-highlights feature: support for single reused posts or per-stream posts linked sequentially, plus an optional wiki archive and a new monthly top-20 post.

Added

  • Previous Stream Clip Link: when using per-stream highlights posts (default mode), LiveSticky automatically links to the previous stream's clip post at the bottom of the body. Also available as a {previous_highlights_url} template placeholder.
  • Reuse Single Highlights Post setting (opt-in): recycles a single permanent master clips post after each stream instead of creating a new post every time. Default is off (creates a new highlights post per stream session).
  • Wiki Clip Archive (opt-in): keeps the full clip history on subreddit wiki pages (one for stream clips, one for the monthly top-20) and links to them from the posts. Off by default; requires wiki to be enabled on your subreddit.
  • Monthly Top 20 Clips Post: publishes the 20 most-watched Twitch clips from the previous calendar month. Features an intuitive schedule selector (Start of month, Middle of month, or End of month) and 24h publish time in your configured Streamer Timezone.
  • Sticky Highlights Post setting: keeps the clip compilation pinned, re-pinning it after each stream if it slips.
  • New {month} template variable for the monthly post, plus dedicated Monthly Top 20 title, header, and footer templates.

Changed

  • Stream highlights post defaults to creating a new post per stream session, allowing per-stream variables like {date} and {stream_title} in post titles. Subreddits wanting a single master sticky post can toggle on Reuse Single Highlights Post.
  • When the wiki archive is off and single post reuse is enabled, the highlights post shows a compact in-body archive of recent streams.

Fixed

  • YouTube livestreams were not being detected on the dashboard even while live. Fixed.
  • The {date} variable now correctly respects the configured Streamer Timezone instead of always using UTC.
